# 第一部分：平台超管后台

## 1.1 数据看板（P1）

| 卡片 | 内容 |
|---|---|
| 租户概览 | 总租户数 / 正常 / 试用 / 已过期 / 已停用 |
| 新增趋势 | 近 30 日新开商城折线图 |
| 营收 | 本月订购收入、待续费金额、续费率 |
| 到期预警 | 7 日内到期租户列表（可直接发提醒/代续费） |
| 平台 GMV | 全租户 GMV 汇总（T+1）、Top 20 活跃租户 |
| 系统健康 | 队列积压、失败任务数、存储用量、短信余量 |

## 1.2 商城管理（P0，多开核心）

**列表页**：商城编号 / 名称 / 联系人手机 / 套餐 / 状态 / 到期时间 / 商品数 / 订单数 / 创建时间
筛选：状态、套餐、到期区间、关键词。支持导出。

**新建商城**（核心流程）
```
填写基本信息 ──> 选择套餐与有效期 ──> 设置店主账号 ──> 分配二级域名 ──> 提交
      │                                                                │
   名称/logo/行业                                              异步初始化任务：
   联系人/手机/备注                                            1. 建 shop 记录
                                                              2. 建店主账号(随机密码/短信通知)
                                                              3. 写套餐快照 shop_package
                                                              4. 灌默认数据种子（分类/运费模板/
                                                                 装修页/交易设置/会员等级/协议）
                                                              5. 建存储目录
                                                              6. 预热缓存
                                                              ──> 返回商城地址 + 后台地址 + 账号
```
要求：**整个建店过程 < 5 秒**，失败可重试且幂等（种子数据用 `shop_id + code` 唯一键去重）。

**其他操作**
- 编辑：改名称/联系人/备注/套餐/到期时间
- 启用 / 停用（停用需填原因，记录审计）
- **免密登录商户后台**（P0）：平台客服排障刚需。生成一次性 token（5 分钟有效、单次使用），进入后商户后台**顶部显示"平台代管理中"横幅**，所有操作日志标记 `by_platform=true`。这是必须有的能力，也是必须审计的能力。
- 数据概览：该租户的商品数/订单数/用户数/GMV/存储用量/短信用量
- 重置店主密码
- 删除（软删 → 归档 → 保留期后清理，二次确认 + 输入商城名称确认）
- 数据导出：应租户要求导出全量业务数据（商品/订单/用户），异步生成 zip

## 1.3 套餐管理（P0）

- 套餐 CRUD：名称、简介、排序、上下架、是否默认试用套餐
- 价格：月/季/年/永久，支持划线价
- **功能项配置**：树形菜单勾选（与商户后台菜单树同源）
- **配额配置**：商品数、员工数、门店数、存储 MB、月短信条数、DIY 页面数、活动数
- 试用套餐：有效期天数、是否允许自助开通
- 变更套餐模板时**不影响已开通租户**（快照机制），提供"批量同步到已有租户"的显式操作

## 1.4 订购与续费管理（P2）

- 订购单：类型（新开/续费/升级/增值）、租户、套餐、周期、金额、状态、支付方式
- 在线支付：微信/支付宝（平台自己的商户号收款）
- 线下开通：平台手工录入（转账场景）
- 退款、发票申请与开票记录
- 续费提醒：到期前 7/3/1 天，短信 + 后台横幅 + 平台侧待办

## 1.5 域名管理（P1）

- 泛域名前缀池：占用检查、保留词黑名单（admin/api/www/store…）
- 自定义域名：租户提交 → 平台审核 → CNAME 校验 → 证书签发 → 生效；支持解绑
- 证书到期自动续签与告警

## 1.6 客户端管理（P2，多开规模化关键）

- **小程序授权列表**：租户名、AppID、授权状态、当前线上版本、审核状态
- **代码模板库**：模板 ID、版本号、更新说明、灰度范围
- **批量发布任务**：选择租户范围 → 生成任务 → 队列限速执行（上传 → 提审 → 发布）
- 任务详情：逐租户状态、失败原因、单个重试
- 审核驳回处理：回写驳回原因，通知租户
- APP 打包任务：租户提交 → 排队 → 构建 → 产物下载链接（含有效期）

## 1.7 平台账号与权限（P0）

- 管理员 CRUD、角色（RBAC）、菜单+按钮级权限
- 操作日志：谁、什么时间、对哪个租户、做了什么、IP、UA
- 登录日志、二次验证（可选）

## 1.8 平台设置（P0/P1）

| 分组 | 项 |
|---|---|
| 存储 | 本地 / 阿里 OSS / 腾讯 COS / 七牛；平台默认配置 |
| 短信 | 阿里云 / 腾讯云 / 其他；模板管理；余量与计费 |
| 物流 | 快递100 / 快递鸟 key；物流公司字典 |
| 微信 | 开放平台第三方平台配置（component_appid/secret/token/aeskey/票据） |
| 支付 | 平台自己的收款商户号（用于收订购费）；服务商配置（可选） |
| 地区 | 省市区数据维护与更新 |
| 站点 | 平台名称、logo、备案号、客服联系方式、登录页文案 |

## 1.9 运维中心（P2）

- 定时任务列表与执行记录（可手动触发、暂停）
- 消息队列监控、死信重投
- 数据库备份（自动/手动、下载、恢复指引）
- 缓存管理（按租户清、全局清）
- 系统版本与升级记录
- 用量统计：各租户存储/短信/接口调用

# 第二部分：租户商户后台

## 2.1 首页看板（P0）

今日：销售额、订单数、支付人数、新增用户、访客数
待办：待发货 / 待退款 / 待评价 / 待提现 / 库存预警 / **套餐到期提醒**
图表：近 7/30 日销售趋势、商品销量 Top10、订单来源端占比

## 2.2 商品（P0）

**商品管理**
- 列表：出售中 / 仓库中 / 已售罄 / 回收站；按分类、关键词、上架状态筛选
- 批量：上架、下架、删除、改分类、改价、改库存
- 导入导出（Excel）
- 库存预警阈值与提醒

**商品发布**
```
基本信息   商品名称、副标题、编码、分类(多选)、品牌、商品图(多图)、视频、
          详情富文本、商品服务(七天无理由/包邮…)、标签
规格库存   单规格 | 多规格(最多3级，自动生成SKU矩阵)
          每个 SKU：价格、划线价、成本价、库存、编码、重量、体积、图片
价格设置   会员价规则、限购、起售数量
物流       运费模板 / 统一运费 / 包邮
其他       虚拟商品(无需物流)、上架方式(立即/放入仓库/定时)、销量基数、排序
```

**商品分类**：三级树、图标、排序、显隐
**品牌**：名称、logo、排序（P1）
**规格库**：规格名 + 规格值复用（如"颜色/尺码"）
**服务保障**：图标 + 名称 + 说明，商品可多选
**商品评价**：列表、审核（先审后显可配）、回复、删除、置顶、追评
**浏览记录/收藏统计**（P1）

## 2.3 订单（P0）

**订单列表**
- Tab：全部 / 待付款 / 待发货 / 待收货 / 已完成 / 已取消 / 售后中
- 筛选：订单号、用户、手机号、下单时间、支付方式、订单来源、配送方式、商品
- 导出 Excel（含收货信息，需权限控制）

**订单详情与操作**
| 操作 | 说明 |
|---|---|
| 改价 | 未付款时可改商品价/运费，记录改价流水 |
| 改地址 | 未发货时可改，记录变更 |
| 发货 | 选物流公司 + 单号；支持**部分发货**（多包裹）、无需物流、自提核销 |
| 批量发货 | 勾选批量 + Excel 导入运单号（对标萤火 2.0 已有能力） |
| 备注 | 商家备注、旗帜标记 |
| 关闭订单 | 未付款订单手动关闭，释放库存 |
| 打印 | 小票/面单，对接电子面单与云打印机（P1） |
| 提醒 | 发货后消息通知、确认收货提醒 |

**售后单**
```
用户申请 ──> 商家审核 ──┬─ 拒绝(填原因) ──> 结束(用户可再次申请/申诉)
   │                  └─ 同意
   │                       ├─ 仅退款 ──> 执行退款(原路/余额) ──> 完成
   │                       └─ 退货退款 ──> 商家填退货地址 ──> 用户填退货单号
   │                                    ──> 商家确认收货 ──> 退款 ──> 完成
超时规则：用户申请超时(收货后N天不可申请)、商家审核超时自动同意(可配)
```
- 退款金额可**部分退**，含运费退不退的选项
- 退款方式：原路退回（微信/支付宝）/ 退到余额
- 退积分、退优惠券、退还库存、扣回已发放佣金 —— 这套"逆向业务"必须在 M1 一起做完，后补代价极大

## 2.4 会员（P0/P1）

- **用户列表**：头像昵称、手机号、来源端、注册时间、消费金额/次数、余额、积分、分销身份、标签
- **用户详情**：资料、订单、余额明细、积分明细、优惠券、地址、下级分销
- 操作：调整余额/积分（填原因，进流水）、加标签、拉黑
- **会员等级**（P1）：等级名、成长值门槛、折扣率、图标、权益说明；自动升级（定时任务）
- **余额充值**（P1）：充值套餐（充100送20）、充值订单、充值流水
- **积分**（P1）：获取规则（下单/签到/评价/邀请）、抵扣规则（多少积分抵1元、最高抵扣比例）、积分明细

## 2.5 营销（P1，全量对标）

| 玩法 | 关键配置 | 备注 |
|---|---|---|
| 优惠券 | 满减/折扣、门槛、有效期(固定/领后N天)、发放总量、每人限领、适用范围(全部/指定分类/指定商品)、领取方式(主动领/新人送/后台发放) | P1 |
| 满减包邮 | 满 X 元减 Y / 满 X 件打折 / 满额包邮（可指定不包邮地区） | P1 |
| 限时折扣 | 商品/SKU 维度，时段生效 | P1 |
| 秒杀 | 场次（每日多时段）、活动商品与秒杀价、限量、限购、库存独立 | P1 |
| 拼团 | 团人数、拼团价、成团有效期、模拟成团、阶梯团（可选）、未成团自动退款 | P1 |
| 砍价 | 砍价商品、最低价、砍价有效期、每人可帮砍次数、砍价算法（随机区间/递减） | P1 |
| 新人礼 | 首次进入/首次下单送券 | P1 |
| 签到 | 每日签到送积分、连续签到奖励、补签（可选） | P1 |
| 积分商城 | 积分兑换商品/优惠券、纯积分或积分+现金 | P1 |
| 组合套餐 | 多商品打包价 | P2 |
| 直播 | 微信小程序直播组件对接 | P3 |

营销通用规则（必须在设计期定死，否则后期算价一团乱）：
- **优惠叠加顺序**：限时折扣/秒杀价 → 会员折扣 → 满减 → 优惠券 → 积分抵扣 → 余额
- 活动商品**互斥**：同一 SKU 同一时段不能既参加秒杀又参加拼团
- 活动库存与商品库存的关系：秒杀/拼团**从商品库存中扣减**（不做独立库存池，避免超卖与对账混乱）
- 算价必须有**统一的价格计算引擎**（单一入口，下单/预览/售后共用），见文档三 §4

## 2.6 分销（P1）

- **分销商**：列表、审核（申请方式：无需申请/需审核/需付费/消费达标）、层级关系树、冻结/解冻
- **分销订单**：订单、下单人、一级/二级分销商、佣金金额、结算状态（待结算/已结算/已失效）
- **佣金结算**：确认收货后 + 售后期（N天）→ 自动结算入账；发生退款则扣回
- **提现**：提现方式（微信零钱/支付宝/银行卡）、最低提现额、手续费、审核 → 打款 → 记录
- **分销设置**：开关、层级（1~2 级）、各级佣金比例（可按商品单独设置）、自购返利、分销商门槛、推广海报模板、佣金说明文案

## 2.7 门店与自提（P1）

- 门店：名称、logo、地址（地图选点）、电话、营业时间、状态
- 店员：绑定门店，仅能核销本店订单
- 核销：扫码 / 输入核销码；核销记录
- 下单时选择自提门店，订单类型区分「快递配送 / 到店自提」
- 同城配送（P3）

## 2.8 内容与装修（P1）

- **页面装修**：可视化拖拽编辑器（左组件库 / 中手机预览 / 右属性面板）
  - 页面类型：首页、自定义页、分类页样式、个人中心样式
  - 组件：轮播图、图片橱窗、导航宫格、商品组、标题栏、富文本、辅助线/空白、优惠券组、秒杀、拼团、公告、视频、客服、搜索栏（含吸顶）、门店
  - 能力：草稿/发布、扫码预览、页面复制、页面模板库、回滚
- **底部导航**：图标+文字+跳转，2~5 个
- **广告位**（P2）：弹窗广告、启动图
- **文章**：分类、文章（富文本）、置顶、显隐
- **公告**：滚动公告
- **帮助中心**（P2）

## 2.9 财务（P1）

- 资金流水：交易收入、退款、充值、佣金支出、提现
- 交易对账：与微信/支付宝账单核对（P2）
- 提现管理：分销佣金提现、用户余额提现（若开放）
- 报表：日/月销售报表、商品销售报表、导出

## 2.10 设置（P0/P1）

## 2.11 客户端（P1/P2）

- **小程序**：模式选择（自填 AppID / 授权托管）
  - 自填：AppID、Secret、上传服务器域名清单指引、下载代码包
  - 托管：扫码授权 → 显示授权状态 → 一键提交发布 → 查看审核状态
  - 小程序码/体验版二维码
- **公众号**：AppID/Secret、菜单配置、网页授权域名指引
- **H5**：默认二级域名、绑定自定义域名、访问二维码
- **APP**：打包配置（应用名、包名、图标、启动图、版本号、证书）、提交打包、下载产物

## 2.12 员工与权限（P0）

- 员工账号：姓名、手机、账号、角色、门店（店员）、状态
- 角色：菜单权限 + 按钮权限（如"能否看到订单手机号""能否导出""能否改价"）
- **数据权限**：店员只看本门店订单（P1）
- 操作日志

## 2.13 我的套餐（P1）

- 当前套餐、到期时间、剩余天数（醒目）
- 配额用量进度条：商品 128/5000、员工 3/10、存储 2.1G/20G、短信 340/1000
- 续费 / 升级：在线下单支付（走平台收款）
- 订购记录、发票申请

# 第三部分：消费者端（uni-app）

## 3.1 页面清单

| 分组 | 页面 | 优先级 |
|---|---|---|
| 首页 | DIY 渲染首页、搜索、公告 | P0 |
| 商品 | 分类页、商品列表、商品详情（规格弹层/参数/服务/评价/详情富文本/推荐）、评价列表、商品搜索 | P0 |
| 购物车 | 列表、选择、改数量、失效商品、结算 | P0 |

## 3.2 端差异处理

| 能力 | 微信小程序 | H5 | 公众号 | APP |
|---|---|---|---|---|
| 登录 | 微信授权 + 手机号快捷 | 手机号验证码 | 网页授权 | 手机号 + 微信登录 |
| 支付 | JSAPI | H5支付/跳转 | JSAPI | APP支付 |
| 分享 | 小程序卡片/朋友圈 | 复制链接 | JSSDK 分享 | 系统分享 |
| 定位 | wx.getLocation | HTML5 定位 | JSSDK | 原生定位 |
| 订阅消息 | ✅ | ❌（走短信） | 模板消息 | 推送（P2） |

**一套 uni-app 代码 + 条件编译**，租户差异通过 `ext.json`/运行时配置注入（shop_id、API 域名、主题色、店铺名、logo）——**业务代码里不允许写租户分支**。

# 第四部分：关键流程

## 4.1 开店流程（平台侧）

```
平台运营 ──> 新建商城 ──> 系统异步初始化 ──> 短信通知店主(后台地址+账号+初始密码)
                                              │
店主首次登录 ──> 强制改密 ──> 引导向导：
                              1) 完善商城信息与 logo
                              2) 配置微信支付（或选择先用余额/货到付款）
                              3) 上传第一个商品
                              4) 配置小程序（自填 or 授权）
                              5) 一键套用行业装修模板
                            ──> 完成，进入看板（显示完成度进度条）
```
> 引导向导是 SaaS 产品的激活率关键。萤火这类系统的典型流失点就在"开完店不知道下一步做什么"。

## 4.2 下单支付流程

```
购物车/立即购买
   ▼
确认订单页 ──> 调用【价格计算引擎】预览：
   商品小计 → 活动价(秒杀/拼团/限时折扣) → 会员折扣 → 满减
   → 优惠券 → 积分抵扣 → 运费(运费模板/包邮规则) → 应付金额
   ▼
提交订单 ──> 校验：库存 / 限购 / 活动有效性 / 地址可配送 / 优惠券可用性
        ──> 【预扣库存】(下单减库存) + 锁定优惠券 + 冻结积分
        ──> 生成订单(待付款)，写入超时关单延时消息
   ▼
调起支付（租户自己的商户号）
   ├─ 支付成功回调 ──> 幂等校验 ──> 订单转「待发货」
   │                          ──> 核销优惠券/积分、发放成长值
   │                          ──> 生成分销佣金记录(待结算)
   │                          ──> 通知：商家(短信/后台)、用户(订阅消息)
   │                          ──> 拼团：加入/创建团，判断是否成团
   └─ 超时未支付 ──> 自动关单 ──> 回滚库存、返还优惠券与积分
```

关键设计：
- **下单减库存**（非付款减库存）：更符合秒杀场景，配合超时关单回滚
- 支付回调必须**幂等**：以商户订单号 + 状态机做乐观锁，重复回调直接返回成功
- 主动查询兜底：回调丢失时由定时任务补偿查询支付状态

## 4.3 发货到完成

```
待发货 ──发货──> 待收货 ──> 用户确认收货 | 超时自动确认(N天) ──> 已完成
                              │
                              ▼
                        待评价 ──评价──> 完成（发积分）
已完成 ──> 售后期内可申请售后（N天）──> 售后流程
已完成 + 售后期满 ──> 分销佣金结算入账
```

## 4.4 租户到期流程

```
到期前 7 天 ──> 短信 + 后台横幅 + 平台待办
到期前 3 天 ──> 再次提醒（横幅升级为强提示）
到期前 1 天 ──> 提醒
到期当日 24:00 ──> 状态转 expired
     ├─ 商户后台：仅可查看数据、发货、处理售后、续费；禁止上新/改价/开活动/装修
     ├─ 用户端：可浏览，下单按钮置灰，提示"店铺休息中"
     └─ 定时任务：仅保留订单收尾（自动确认收货、售后超时）
续费成功 ──> 立即恢复（缓存刷新 < 10s）
过期 90 天未续 ──> 归档（数据只读，提供导出），再 90 天 ──> 物理清理（需二次确认+邮件通知）
```

## 4.5 小程序批量升级流程（P2）

```
平台发布新代码模板(template_id) ──> 创建批量任务(选择租户范围/灰度比例)
   ▼
队列限速执行，逐租户：
   注入 ext.json(shop_id/域名/名称) ──> 代上传代码 ──> 代提交审核
   ▼
微信审核回调 ──┬─ 通过 ──> 自动发布(或人工确认后发布) ──> 记录线上版本
              └─ 驳回 ──> 记录原因 ──> 通知租户 ──> 人工介入
```
限制：微信对提审频率有限制，任务需限速、可暂停、失败可单独重试；灰度先跑 5 个租户再全量。
