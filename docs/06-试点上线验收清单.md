# 试点上线验收清单（2026 年内）

功能测试怎么登录、先测哪几条，见 **`docs/07-测试手册.md`**。本页是年底接待真实商家的闸门，不是日常用例表。

> 成功标准（12 月 31 日前只认这一条）：**至少 1 家真实商家，用真实微信商户号收款，完成发货或自提，并能处理一笔退款；顾客能从 H5 或自填 AppID 的小程序下单。**
>
> 不是「功能全部做完」，也不是「对外规模化招商」。
>
> 用法：每周对照仓库勾一次。□ 未做　▣ 已过　— 砍掉/后补

---

## 必须过（不过就不能接待真实顾客）

### A. 钱能进、能退

- [ ] 试点店在商户后台填入**自己的**微信商户号（密钥只显示掩码，AES 能解开）
- [ ] H5 下单 → 拉起微信支付 → 回调把订单打成已支付（重复回调不重复入账）
- [ ] 未支付订单超时自动关单，库存回滚
- [ ] 仅退款走通一笔，钱原路退回，订单/售后状态一致
- [ ] 退货退款走通一笔（若试点只做虚拟/自提，可只做仅退款，在此注明）

### B. 货能出

- [ ] 发布 1 个多规格商品，C 端规格、库存、价格联动正确
- [ ] 快递：后台填单号发货 → 顾客订单变为待收货
- [ ] 或自提：选门店下单 → 核销码能核销且不能重复核销
- [ ] 确认收货后订单完结（人工或超时自动）

### C. 店能开出来、看起来是自己的

- [ ] 超管新建商城 → 店主能登录（菜单 = 套餐 ∩ 角色）
- [ ] 装修：编辑 → 保存草稿 → **设为首页** → **发布** → H5 首页就是这页
- [ ] 页面背景、轮播/导航/商品组在 C 端可见
- [ ] 底部导航可保存，C 端能点到对应页

### D. 生产环境不裸奔

- [ ] 用 `docker-compose.prod.yml` 在预发/生产拉起，`.env` 里 `CHANGE_ME` 全部换掉
- [ ] `JWT_SECRET` / `AES_KEY` 为随机值；**AES_KEY 上线后不更换**
- [ ] HTTPS（泛域名或已签发的自定义域）访问 H5 / 商户后台
- [ ] 上传图能被 C 端加载（store-api 与 client-api 共享 uploads 卷）
- [ ] MySQL 每日备份可恢复（至少演练一次 restore 到空库）
- [ ] 支付、下单、登录错误有日志可查

### E. 安全底线（抽测即可，但必须做）

- [ ] 店 A 的 token 调店 B 的订单/商品，必须 403/404
- [ ] 支付密钥接口不回显明文
- [ ] 上传接口不能传可执行脚本当图片

## 可以后补（试点期用变通，不挡第一家店）

| 项 | 试点期怎么过 | 建议补的时间 |
|---|---|---|
| 对象存储 OSS | 继续本地盘 + 备份卷 | 2027 Q1，图多了再迁 |
| 短信验证码 | 先用微信登录 / 固定测试号 | 有真实顾客量再接 |
| 物流轨迹 | 发货只填单号，顾客自行查 | 接快递 100 不挡上线 |
| 自定义域名 + Let's Encrypt | 先用 `店铺code.你的域名` | 商家强烈要求再开 ACME |
| 小程序 | **商家自填 AppID 上传** | 第三方托管放到明年 |
| 营销叠加（券+满减+秒杀） | 试点店先开一种玩法 | 第二家店前做回归 |
| 分销佣金 / 提现 | 试点可不开放 | 有分销需求再验收退款扣回 |
| 积分 / 签到 / 积分商城 | 可关 | 不进试点范围 |
| 装修里文章/视频/头条 | 有素材再用 | 不挡卖货 |
| 运维中心 UI | 先看容器日志 + 备份脚本 | M5 |

## 按月怎么勾（对着上面 A–E）

| 月 | 只做这些 | 月底必须能演示 |
|---|---|---|
| **9 月** | A + B + E | 预发环境：真实微信支付一笔、发货一笔、退款一笔 |
| **10 月** | C + D | 试点店装修发布；H5 或小程序顾客能买 |
| **11 月** | 扩到 ≤3 家；只修试点炸的问题 | 第二家店店主能独立上架发货 |
| **12 月** | **冻结功能**；SOP + 值班 | 达到文首成功标准，不再加模块 |

每周站会只问三句：必须过还差哪条？有没有人在做砍掉清单里的事？试点商家卡在哪？

## 试点商家开通清单（给店主，一页纸）

1. 营业执照、微信商户号、（可选）小程序 AppID  
2. 超管开通商城，发给店主账号  
3. 店主：支付设置 → 上架 10 个以内商品 → 运费或门店  
4. 装修首页并**发布**（只保存不算）  
5. 用顾客微信走一笔 0.01 或真实低价单，确认到账  
6. 发货或核销，再退一笔，确认账平  

平台侧留：店主微信、商户号到账人、出问题找谁（1 个值班号）。

## 现状备忘（2026-08-30，避免误判「已经有了」）

| 能力 | 仓库里 | 试点含义 |
|---|---|---|
| 微信支付 H5 预下单 / 回调 | 有 `WxPayGateway` | **必须用试点店真实商户号打通**，demo 密钥不算过 |
| 文件存储 | 仅本地磁盘 | 试点可用，记得备份 |
| 短信 | 无独立短信服务 | 后补 |
| 装修首页 / 背景 / 组件库 | 刚补过一轮 | 必须走「发布」验收，不要只看编辑器 |
| APP 打包 / 第三方批量发布 | 未做 | 砍掉 |
| 生产 compose | 有手册 | D 组还没在真实机器上勾过就不算过 |

勾完「必须过」再接待真实顾客。其余争议一律按「后补 / 砍掉」处理，不要再开新需求单。
