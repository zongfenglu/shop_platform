# 测试手册（开发机部署，测试机浏览器访问）

给功能测试同学用。对着浏览器点就行，不需要会写代码。

环境跑在**开发同学自己的电脑**上，测试用**自己电脑的浏览器**访问，不要打开 `localhost`（那是开发机自己，测试机上打不开）。

目标：把「开店 → 上架 → 下单 → 发货/售后」主链路走通。年底真微信支付见 `docs/06-试点上线验收清单.md`，不是本期每天的用例表。

---

## 0. 先跟开发要三个网址

两台电脑必须在**同一个局域网**（同一 Wi‑Fi / 网线，或连了公司 VPN）。开发把下面 IP 填好发给你（不要用 `127.0.0.1`）：

| 端 | 打开（把 `开发机IP` 换成他发给你的数字） | 登录 |
|---|---|---|
| 平台超管 | `http://192.168.10.110:8090` | `admin` / `admin123` |
| 商户后台 | `http://192.168.10.110:8091` | 店铺编号 **`demo`**，账号 `admin` / `123456` |
| 顾客 H5 | `http://192.168.10.110:8092` | 首次要填店铺 ID `1001`，见第 1 节 |

示例：开发机是 `192.168.1.23`，超管就是 http://192.168.1.23:8090 。

商户登录必须填店铺编号 **`demo`**，只填账号密码会进不去。

打不开时先看第 3 节，不要直接提「网站挂了」。

---

## 1. 第一次打开 H5（必做）

用 IP 访问时没有独立域名，H5 认不出是哪家店。首页如果提示「未能识别商城」：

1. 在输入框填 **`1001`**（演示店的数字 ID，不要填 `demo`）
2. 保存后再逛首页 / 分类 / 购物车

刷新后一般会记住。若仍然空、或提示无法识别商城：没填 `1001`，或开发还没导入演示数据。

---

## 2. 打不开先对这几条

测试同学不用装软件。打不开时按顺序排除：

1. 地址是不是 `http://开发机IP:端口`，有没有误写成 `localhost`
2. 两台电脑是不是同一个 Wi‑Fi / 同一网段（手机热点和公司网不是一回事）
3. 开发电脑是否还开着、有没有休眠、Docker 是否还在跑
4. 换一台电脑或手机（连同一 Wi‑Fi）打开同一个链接，仍不通就是开发机防火墙或服务没起来

通了超管、商户，但 H5 空白：先填 `1001`。

---

## 3. 环境谁负责

- **测试**：浏览器能打开三个网址即可。
- **开发**：在自己电脑上把 Docker 拉起来，把局域网 IP 和三个链接发给测试；测试期间电脑别休眠。

开发机启动（测试不用敲）：

```powershell
cd d:\owner\shop_platform\docker
docker compose up -d --build --remove-orphans
```

演示数据：

```powershell
d:\owner\shop_platform\docker\load-demo-seed.cmd
```

会灌入：演示店 `demo`、分类「演示分类」、商品 A/B/C、两张券、一条满减。

开发怎么查 IP、怎么放行端口，见文末附录。

---

## 4. 建议测试顺序（先主路径）

按这个顺序测，前面过了再铺开，避免一上来扎进营销细节。

### 第 1 天：店能开、货能上、C 端能看见

1. **超管**登录 → 商城管理里能看到「演示商城」→ 点进详情，看停用 / 重置密码 / 免密进入商户后台。
2. **超管**新建一家测试店（不要覆盖 demo）→ 记下店铺编号和店主密码 → 用新店登录商户后台。
3. **商户（demo）** 商品 → 分类管理：建一级 / 二级分类，上传分类图，隐藏后再到 H5「分类」Tab 核对。
4. **商户** 发布一个**单规格**商品（选分类、主图、价、库存、运费模板）→ 上架。
5. **商户** 再发布一个**多规格**商品（颜色/尺码），核对 SKU 价和库存。
6. **H5** 填 `1001` → 首页或分类能看到刚上的商品 → 进详情，图和规格切换要跟着变价/库存。

### 第 2 天：单能下、能发、能退

7. **H5** 加入购物车 → 结算（快递地址）→ 提交订单。  
   - 本地**通常拉不起真微信支付**。能生成「待付款」订单就算下单通。  
   - 不要把「支付按钮点了没跳出微信」单独当成 P0 缺陷，除非开发已配好测试商户号并告知可以测支付。
8. **商户** 订单列表能看到该单 → 若能改成已支付（或开发帮你把单打成已支付）→ **发货**填物流单号 → H5 订单变为待收货。
9. **商户** 售后：对一笔已支付订单做「仅退款」，看状态两边是否一致。
10. **商户** 装修：改首页（轮播/导航/商品组）→ **保存** → **设为首页** → **发布**（只保存不算）→ H5 刷新应是新首页。
11. **商户** 装修 → 分类页：换三种样式（一级大图 / 一级小图 / 二级），H5「分类」Tab 跟着变。

### 第 3 天起：铺开回归

超管：套餐、停用商城后再打开 H5 应进不去。  
商户：会员、优惠券、满减、门店自提、员工账号、支付设置（密钥只显示掩码）。  
H5：领券、满减金额、自提选门店。

## 5. 分端检查清单

打勾用。□ 未测　▣ 通过　✗ 有缺陷（单号写备注）

### 5.1 平台超管（8090）

- [ ] 登录 / 退出 / 错误密码有提示
- [ ] 商城列表、筛选、进入详情
- [ ] 新建商城：店主能立刻用发的账号登录
- [ ] 免密进入商户后台，顶上有「平台代管理中」
- [ ] 重置店主密码后，旧密码不能登、新密码能登
- [ ] 停用商城后，该店商户后台和 H5 不可用；再启用恢复
- [ ] 套餐能看、能改功能勾选（改模板**不应**悄悄改掉已有店，除非点了同步）
- [ ] 平台账号：建账号、改角色、重置密码；取消重置不能提示成功
- [ ] 角色「查看权限」是分组树，不是一长串英文权限码

### 5.2 商户后台（8091）

- [ ] 登录必须带店铺编号 `demo`
- [ ] 看板能打开（数字允许是 0，不能白屏 / 500）
- [ ] 商品列表：上架 / 下架 / 编辑
- [ ] 分类：三级树、排序、显示隐藏、有子分类或商品占用时不能删
- [ ] 发布：必填校验；详情是富文本不是一坨 HTML 源码
- [ ] 多规格：改一个 SKU 库存，C 端对应规格库存变
- [ ] 订单：列表 Tab、详情、发货
- [ ] 售后：列表与操作
- [ ] 装修：草稿 / 设为首页 / **发布**；底部导航保存后 H5 能点
- [ ] 分类页模板三种样式
- [ ] 设置：运费模板；支付设置（没配商户号时保存应明确失败，不要假成功）
- [ ] 营销：优惠券、满减能建；C 端结算金额要算对（见下节金额）
- [ ] 门店：能建门店；H5 选自提时能选到
- [ ] 员工：建员工、改角色；用员工账号登录，菜单符合角色
- [ ] 会员 / 等级 / 充值方案页面能打开

### 5.3 顾客 H5（8092）

- [ ] 未填 `1001` 时有说明，填了才能看店
- [ ] 首页：无装修走分类+商品；有发布装修则显示装修
- [ ] 分类 Tab 与后台模板一致；点分类进列表，能返回分类
- [ ] 商品详情：主图、规格、富文本、加购
- [ ] 购物车：改数量、删除
- [ ] 下单：地址 / 自提门店；库存不足不能超卖
- [ ] 我的订单：状态与商户后台一致
- [ ] 优惠券 / 满减：门槛不够不能用；够了金额对

**金额抽查（演示数据，导入 seed 后）**

| 场景 | 预期（运费模板：首件 8 元，续件 5 元） |
|---|---|
| 只买商品 C（40 元） | 未满 99，无满减；运费 8；应付约 48 |
| 只买商品 A（100 元） | 满 99 减 10；运费 8；应付约 98 |
| A + B（180 元） | 满 99 减 10；两件运费 8+5=13；应付约 183 |
| 再凑到满 199 | 减 20 且包邮（规则名「满199减20（包邮）」） |

数字以页面为准，差 1 分钱也要记缺陷（看是展示四舍五入还是算错）。

## 6. 先不要当成缺陷的

这些是**已知未做或本地故意关掉的**，不要重复提「功能没有」除非开发说已经交付：

| 现象 | 说明 |
|---|---|
| H5 点支付，微信没起来 | 本地默认没有可用的微信商户号。后台「设置 → 支付」也没配真密钥时，这是预期。 |
| 下单后不是立刻关单 | 未支付关单大约 **5 分钟**扫一次，不是秒关。 |
| 收不到短信验证码 | 没接短信通道。 |
| 没有物流轨迹地图 | 发货只填单号，顾客自行查。 |
| 没有 APP 下载 / 应用商店 | 今年不做。 |
| 没有小程序批量提审、第三方开放平台 | 今年不做。试点若测小程序，走商家自填 AppID。 |
| 平台订购套餐在线收款、发票 | 不做。超管给店开通即可。 |
| 图片不是 OSS | 存在服务器磁盘，刷新能看到就算过。 |
| 演示商品图裂开 | seed 里用了占位图地址，可能被墙。用商户后台重新传一张图再验。 |

支付、短信、物流轨迹：**不要为了测通去造假成功**。没配通道就记「未测 / 阻塞」，等开发给测试商户号或 mock 说明。

---

## 7. 怎么提缺陷

一条缺陷里请写全：

1. **端**：超管 / 商户 / H5  
2. **账号**：例如 demo / admin  
3. **步骤**：从哪进、点了什么  
4. **期望** vs **实际**（截图）  
5. **是否必现**  
6. 若是钱、库存、跨店：单号、商品名、操作前后数量  

严重级别建议：

- **P0**：钱错了、库存超卖、A 店能看到 B 店数据、停用店还能买  
- **P1**：主路径走不通（发不了货、发布不了商品、装修发布无效）  
- **P2**：展示错、文案错、交互别扭  
- **P3**：建议

跨店越权请抽测：用店 A 登录后，不要用店 B 的商品/订单 ID 去改数据（或让开发给两个店）。必须失败，且不能把 B 的数据露出来。

## 9. 每日开始前 1 分钟

- 用开发发的 **IP 网址** 三个都能打开（不是 localhost）
- 超管、demo 商户能登录
- H5 填了 `1001` 能看到商品

有一项不行，先找开发，不要在坏环境上堆缺陷单。

测完主路径（第 4 节 1～11）就可以开第二家店做回归。真微信支付放到试点验收，不要卡在本期第一轮。

## 附录：开发机怎么把环境给测试用

1. Docker Desktop 开着，执行第 3 节的 `docker compose up -d`。
2. 查局域网 IPv4（不要用 `127.0.0.1`，不要用 `172.` 开头的 Docker 网段）：

```powershell
ipconfig
```

看「无线局域网适配器 WLAN」或「以太网」下面的 **IPv4 地址**，例如 `192.168.1.23`。

3. 放行三个网页端口（管理员 PowerShell 执行一次即可）：

```powershell
New-NetFirewallRule -DisplayName "shop-platform-test" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8090,8091,8092
```

4. 自己先用手机（连同一 Wi‑Fi）打开 `http://你的IP:8090`，通了再发给测试。
5. 发给测试的消息可以这样写：

```
环境在我电脑上，请不要用 localhost。
超管  http://192.168.x.x:8090   admin / admin123
商户  http://192.168.x.x:8091   店铺编号 demo，admin / 123456
H5    http://192.168.x.x:8092   首次填店铺 ID 1001
两台电脑连同一个 Wi-Fi。测的时候我这台不要关机、不要休眠。
```

6. 改过 H5 之后要重新 `docker compose up -d --build h5`，测试机才会拿到新页面。
7. 电脑休眠、断网、Docker 退出，测试机立刻全部打不开，这是正常的。
