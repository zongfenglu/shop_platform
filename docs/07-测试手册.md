# 测试手册（开发机部署，测试机浏览器访问）

给功能测试同学用。对着浏览器点就行，不需要会写代码。

环境跑在 **Linux 测试服务器**（或开发机 Docker）上，测试用自己电脑的浏览器访问，不要打开 `localhost`（那是测试机自己，别人打不开）。

目标：把「开店 → 上架 → 下单 → 发货/售后」主链路走通。年底真微信支付见 `docs/06-试点上线验收清单.md`，不是本期每天的用例表。

---

## 0. 先跟开发要三个网址

两台电脑必须能访问到测试服务器（同一局域网，或域名已解析到服务器公网 IP）。开发把下面网址发给你：

| 端 | 打开（开发会发真实域名；默认如下） | 登录 |
|---|---|---|
| 平台超管 | `http://admin.shop.test` | `admin` / `admin123` |
| 商户后台 | `http://store.shop.test` | 店铺编号 **`demo`**，账号 `admin` / `123456` |
| 顾客 H5 | `http://demo.shop.test` | 不用填店铺 ID，域名就是演示店 |

如果开发改过 `PLATFORM_BASE_DOMAIN`，把上面的 `shop.test` 换成那个域名即可。

商户登录必须填店铺编号 **`demo`**，只填账号密码会进不去。

打不开时先看第 3 节，不要直接提「网站挂了」。

旧的 `http://开发机IP:8090` 仍可用，优先用域名。

---

## 1. 第一次打开 H5

用 `http://demo.shop.test`（或开发给的店铺子域名）打开即可，**不用填店铺 ID**。

只有在用 IP:端口访问时，H5 才认不出是哪家店。那时首页会提示「未能识别商城」：

1. 在输入框填 **`1001`**（演示店的数字 ID，不要填 `demo`）
2. 保存后再逛首页 / 分类 / 购物车

---

## 2. 打不开先对这几条

测试同学不用装软件。打不开时按顺序排除：

1. 地址是不是开发发的域名（`http://admin.…` / `store.…` / `demo.…`），有没有误写成 `localhost`
2. 本机 hosts 或 DNS 是否已指向开发机（打不开域名时，用开发给的 IP:8090 对照）
3. 两台电脑是不是同一个 Wi‑Fi / 同一网段（手机热点和公司网不是一回事）
4. 开发电脑是否还开着、有没有休眠、Docker 是否还在跑
5. 换一台电脑或手机（连同一 Wi‑Fi）打开同一个链接，仍不通就是开发机防火墙或服务没起来

通了超管、商户，但 H5 空白：确认打开的是 `demo.` 开头的地址，不是 IP。

---

## 3. 环境谁负责

- **测试**：浏览器能打开三个网址即可。
- **开发**：在 **Linux 测试服务器**（或本机 Docker）把环境拉起来，把域名发给测试。

测试服务器启动（测试同学不用敲）：

```bash
cd /path/to/shop_platform/docker
docker compose up -d --build --remove-orphans
chmod +x seed/load.sh
./seed/load.sh
```

会灌入：演示店 `demo`、分类「演示分类」、商品 A/B/C、两张券、一条满减。

域名、防火墙、更新代码见文末附录（Linux）。

## 4. 建议测试顺序（先主路径）

按这个顺序测，前面过了再铺开，避免一上来扎进营销细节。

### 第 1 天：店能开、货能上、C 端能看见

1. **超管**登录 → 商城管理里能看到「演示商城」→ 点进详情，看停用 / 重置密码 / 免密进入商户后台。
2. **超管**新建一家测试店（不要覆盖 demo）→ 记下店铺编号和店主密码 → 用新店登录商户后台。
3. **商户（demo）** 商品 → 分类管理：建一级 / 二级分类，上传分类图，隐藏后再到 H5「分类」Tab 核对。
4. **商户** 发布一个**单规格**商品（选分类、主图、价、库存、运费模板）→ 上架。
5. **商户** 再发布一个**多规格**商品（颜色/尺码），核对 SKU 价和库存。
6. **H5** 填 `1001` → 首页或分类能看到刚上的商品 → 进详情，图和规格切换要跟着变价/库存。

### 第 2 天：单能下、能发、能退

7. **H5** 加入购物车 → 结算（快递地址）→ 提交订单。  
   - 本地**通常拉不起真微信支付**。能生成「待付款」订单就算下单通。  
   - 不要把「支付按钮点了没跳出微信」单独当成 P0 缺陷，除非开发已配好测试商户号并告知可以测支付。
8. **商户** 订单列表能看到该单 → 若能改成已支付（或开发帮你把单打成已支付）→ **发货**填物流单号 → H5 订单变为待收货。
9. **商户** 售后：对一笔已支付订单做「仅退款」，看状态两边是否一致。
10. **商户** 装修：改首页（轮播/导航/商品组）→ **保存** → **设为首页** → **发布**（只保存不算）→ H5 刷新应是新首页。
11. **商户** 装修 → 分类页：换三种样式（一级大图 / 一级小图 / 二级），H5「分类」Tab 跟着变。

### 第 3 天起：铺开回归

超管：套餐、停用商城后再打开 H5 应进不去。  
商户：会员、优惠券、满减、门店自提、员工账号、支付设置（密钥只显示掩码）。  
H5：领券、满减金额、自提选门店。

## 5. 分端检查清单

打勾用。□ 未测　▣ 通过　✗ 有缺陷（单号写备注）

### 5.1 平台超管（8090）

- [ ] 登录 / 退出 / 错误密码有提示
- [ ] 商城列表、筛选、进入详情
- [ ] 新建商城：店主能立刻用发的账号登录
- [ ] 免密进入商户后台，顶上有「平台代管理中」
- [ ] 重置店主密码后，旧密码不能登、新密码能登
- [ ] 停用商城后，该店商户后台和 H5 不可用；再启用恢复
- [ ] 套餐能看、能改功能勾选（改模板**不应**悄悄改掉已有店，除非点了同步）
- [ ] 平台账号：建账号、改角色、重置密码；取消重置不能提示成功
- [ ] 角色「查看权限」是分组树，不是一长串英文权限码

### 5.2 商户后台（8091）

- [ ] 登录必须带店铺编号 `demo`
- [ ] 看板能打开（数字允许是 0，不能白屏 / 500）
- [ ] 商品列表：上架 / 下架 / 编辑
- [ ] 分类：三级树、排序、显示隐藏、有子分类或商品占用时不能删
- [ ] 发布：必填校验；详情是富文本不是一坨 HTML 源码
- [ ] 多规格：改一个 SKU 库存，C 端对应规格库存变
- [ ] 订单：列表 Tab、详情、发货
- [ ] 售后：列表与操作
- [ ] 装修：草稿 / 设为首页 / **发布**；底部导航保存后 H5 能点
- [ ] 分类页模板三种样式
- [ ] 设置：运费模板；支付设置（没配商户号时保存应明确失败，不要假成功）
- [ ] 营销：优惠券、满减能建；C 端结算金额要算对（见下节金额）
- [ ] 门店：能建门店；H5 选自提时能选到
- [ ] 员工：建员工、改角色；用员工账号登录，菜单符合角色
- [ ] 会员 / 等级 / 充值方案页面能打开

### 5.3 顾客 H5（8092）

- [ ] 未填 `1001` 时有说明，填了才能看店
- [ ] 首页：无装修走分类+商品；有发布装修则显示装修
- [ ] 分类 Tab 与后台模板一致；点分类进列表，能返回分类
- [ ] 商品详情：主图、规格、富文本、加购
- [ ] 购物车：改数量、删除
- [ ] 下单：地址 / 自提门店；库存不足不能超卖
- [ ] 我的订单：状态与商户后台一致
- [ ] 优惠券 / 满减：门槛不够不能用；够了金额对

**金额抽查（演示数据，导入 seed 后）**

| 场景 | 预期（运费模板：首件 8 元，续件 5 元） |
|---|---|
| 只买商品 C（40 元） | 未满 99，无满减；运费 8；应付约 48 |
| 只买商品 A（100 元） | 满 99 减 10；运费 8；应付约 98 |
| A + B（180 元） | 满 99 减 10；两件运费 8+5=13；应付约 183 |
| 再凑到满 199 | 减 20 且包邮（规则名「满199减20（包邮）」） |

数字以页面为准，差 1 分钱也要记缺陷（看是展示四舍五入还是算错）。

## 6. 先不要当成缺陷的

这些是**已知未做或本地故意关掉的**，不要重复提「功能没有」除非开发说已经交付：

| 现象 | 说明 |
|---|---|
| H5 点支付，微信没起来 | 本地默认没有可用的微信商户号。后台「设置 → 支付」也没配真密钥时，这是预期。 |
| 下单后不是立刻关单 | 未支付关单大约 **5 分钟**扫一次，不是秒关。 |
| 收不到短信验证码 | 没接短信通道。 |
| 没有物流轨迹地图 | 发货只填单号，顾客自行查。 |
| 没有 APP 下载 / 应用商店 | 今年不做。 |
| 没有小程序批量提审、第三方开放平台 | 今年不做。试点若测小程序，走商家自填 AppID。 |
| 平台订购套餐在线收款、发票 | 不做。超管给店开通即可。 |
| 图片不是 OSS | 存在服务器磁盘，刷新能看到就算过。 |
| 演示商品图裂开 | seed 里用了占位图地址，可能被墙。用商户后台重新传一张图再验。 |

支付、短信、物流轨迹：**不要为了测通去造假成功**。没配通道就记「未测 / 阻塞」，等开发给测试商户号或 mock 说明。

## 7. 怎么提缺陷

一条缺陷里请写全：

1. **端**：超管 / 商户 / H5  
2. **账号**：例如 demo / admin  
3. **步骤**：从哪进、点了什么  
4. **期望** vs **实际**（截图）  
5. **是否必现**  
6. 若是钱、库存、跨店：单号、商品名、操作前后数量  

严重级别建议：

- **P0**：钱错了、库存超卖、A 店能看到 B 店数据、停用店还能买  
- **P1**：主路径走不通（发不了货、发布不了商品、装修发布无效）  
- **P2**：展示错、文案错、交互别扭  
- **P3**：建议

跨店越权请抽测：用店 A 登录后，不要用店 B 的商品/订单 ID 去改数据（或让开发给两个店）。必须失败，且不能把 B 的数据露出来。

## 附录：Linux 测试服务器怎么给测试用

环境跑在 Linux 上，用 `docker/docker-compose.yml`（一个 JVM 的试点栈），**不要**用 `docker-compose.prod.yml`。

### 1. 机器准备

Docker Engine 24+ 和 Compose v2。不需要装 JDK / Maven / Node。

```bash
docker compose version
# 若没有 compose 插件：apt/yum 安装 docker-compose-plugin
```

确认 Docker 已安装。**80 端口留给宿主机 Nginx**。

```bash
docker compose version
ss -lntup | grep ':80 '
```

### 2. 拉代码并启动

只需改域名：编辑 `docker/.env` 里的 `PLATFORM_BASE_DOMAIN`（例如 `example.com`）。

```bash
git clone <仓库地址> shop_platform   # 已有仓库则 git pull
cd shop_platform/docker
# vi .env   →  PLATFORM_BASE_DOMAIN=你的域名

docker compose up -d --build --remove-orphans
```

首次构建约 10～20 分钟。日志出现 `Started ShopAppApplication` 后：

```bash
chmod +x seed/load.sh scripts/install-host-nginx.sh scripts/setup-local-domains.sh
./seed/load.sh
sudo bash scripts/install-host-nginx.sh
```

之后打开 `http://admin.你的域名`、`http://store.你的域名`、`http://demo.你的域名`。

### 3. 域名解析

DNS 把 `admin` / `store` / `demo` / `*` 的 A 记录指到这台 Linux 的 IP。没有 DNS 时：

```bash
./scripts/setup-local-domains.sh
sudo ./scripts/setup-local-domains.sh --apply
```

Windows 测试机把打印的五行加到 `C:\Windows\System32\drivers\etc\hosts`。手机改不了 hosts，必须走真 DNS。

改域名后：改 `.env` → `docker compose up -d --force-recreate app` → `sudo bash scripts/install-host-nginx.sh`。

### 4. 防火墙

云厂商安全组先放行 **TCP 80**（以及若仍用端口访问：8090–8092）。机器上：

```bash
# firewalld
sudo firewall-cmd --permanent --add-port=80/tcp
sudo firewall-cmd --reload

# 或 ufw
sudo ufw allow 80/tcp
sudo ufw reload
```

本机验证（不依赖 DNS）：

```bash
curl -sI -H "Host: admin.你的域名" http://127.0.0.1/ | head
curl -s  -H "Host: demo.你的域名" http://127.0.0.1/api/diy/home
```

第二条应返回 `"code":0`。

### 5. 更新代码后怎么启动

代码是打进镜像的，只 `restart` 不会带上新代码：

```bash
cd /path/to/shop_platform
git pull
cd docker
docker compose up -d --build app          # 只改了 Java
docker compose up -d --build admin-web    # 只改了超管前端
docker compose up -d --build store-web
docker compose up -d --build h5
# 改了域名：改 .env 的 PLATFORM_BASE_DOMAIN，然后
# docker compose up -d --force-recreate app && sudo bash scripts/install-host-nginx.sh
# 前后端都改了：
docker compose up -d --build --remove-orphans
```

不要 `docker compose down -v`，会删 MySQL 数据。

### 6. 发给测试的文案

```
环境在 Linux 测试服务器上，请不要用 localhost。
超管  http://admin.你的域名     admin / admin123
商户  http://store.你的域名     店铺编号 demo，admin / 123456
H5    http://demo.你的域名
```

无 DNS 时附上 hosts 五行。

Windows 开发机备忘：`docker/seed/load.cmd`、`docker/scripts/setup-local-domains.ps1`，端口 8090–8092 仍可用。
